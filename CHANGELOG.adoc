= Changelog

== [0.2.12] - 2026-10-20

=== Changed

* A desktop build asks `Use local docs` or `Use remote docs` before any search, and remembers the choice in the local-content cache. `Use remote docs` leaves playbook URLs remote. `Use local docs` opens the search window with no second Yes/No prompt.
* Each source row has a Download, Move, or Local button. Move and Download put the repo at `<hive>/github.com/<org>/<repo>` (creating the org folder) and write `.antora-source-id`. A non-empty wrong folder is left alone and the row shows an error. `ANTORA_LOCAL_SOURCES_MODE=ask|local|remote` changes the remembered choice. CI still never scans.

== [0.2.11] - 2026-10-20

=== Changed

* CI never scans the local disk for clones and never opens the search window. `CI`, `GITHUB_ACTIONS`, `TF_BUILD`, `GITLAB_CI`, CircleCI, Buildkite, and Jenkins leave playbook URLs remote unless a cache entry still points at a real local path. `ANTORA_LOCAL_SOURCES_CONFIRM_SEARCH=yes` does not override that. Outside CI, `yes` may still scan and `no` stays cache-only.

== [0.2.10] - 2026-10-20

=== Changed

* The Windows search window asks "Search for local Antora docs?" and explains that the build looks for local clones, then caches downloads when none are found. The How section is gone. The scripting bypass and Yes/No buttons stay.
* Playbook source URLs stay in one list (remote URL and status). Status moves from waiting to searching, then found, not found, or validated from the real cache check and resolver report. The activity log stays under that list. The last line is green "Finished." or red "Finished with errors."

== [0.2.9] - 2026-10-20

=== Changed

* The Windows search window title is "Antora Local content search" on the Yes/No confirm view and on the later progress view.

== [0.2.8] - 2026-10-20

=== Changed

* On a Windows desktop, disk-search confirmation is a sectioned Yes/No window (Why, What, How, scripting bypass) and later progress stays in that window's scrollable log.
* The ASCII stderr banner and Y/n prompt are only used for CI, headless sessions, `ANTORA_LOCAL_SOURCES_UI=tty`, the `ANTORA_LOCAL_SOURCES_CONFIRM_SEARCH` bypass, or when the window cannot be created (one line says why).
* Phase lines go to the Antora logger once, as ASCII (`-`, `...`), and are not copied to stderr. Em dashes and ellipses no longer show up as console mojibake.

== [0.2.7] - 2026-10-20

=== Fixed

* Disk-search banner wraps long lines inside the ASCII frame so the right border stays on the same row.

== [0.2.6] - 2026-10-20

=== Fixed

* Disk-search banner is printed once, on stderr, with an ASCII frame (`-`, `|`). The Antora logger gets a one-line ASCII summary only, so Windows consoles no longer show a mojibake duplicate of the box drawing.
* Confirmation prompt and banner say "remote source(s)" (space between the words).

== [0.2.5] - 2026-10-20

=== Fixed

* Syntax error in disk-search confirmation branch (`Unexpected token ')'`) prevented pack load via facto-stack.

== [0.2.4] - 2026-10-20

=== Changed

* Visible progress before slow work: stderr + logger banners explaining disk search (why/what/how), cache-only fast path, D binary download, and elapsed time when search completes.

== [0.2.3] - 2026-10-20

=== Added

* Interactive confirmation before disk search when cache paths are missing/invalid (TTY). Env `ANTORA_LOCAL_SOURCES_CONFIRM_SEARCH=yes|no` bypasses the prompt for scripts; bypass text is included in the question for agent/LLM use.
* Skip D/MFT when all remotes still validate from cache.

== [0.2.2] - 2026-10-20

=== Changed

* **Canonical marker:** fixed filename `.antora-source-id` with stable `id:` + `url:` lines in the body (id is not encoded in the path). MFT / walks search that basename only, then read files to match.
* Hash filenames `.antora-src-*` are deprecated but still honored when present.
* Cache / report use `markerId` (32 hex); cache format version 2.

== [0.2.1] - 2026-10-20

=== Changed

* Windows drive-wide search defers to D resolver NTFS **MFT** scan (`searchMethod: auto`); Node skips parallel drive walks on win32.
* Warn when D resolver is missing on Windows (MFT volume pass skipped).

== [0.2.0] - 2026-10-20

=== Added

* Search order: playbook directory first, then ancestors (excluding already-searched child subtrees, capped by `maxUpwardHops`), then `searchRoots`, then other drives in parallel (Node worker threads; D `std.parallelism`).
* Duplicate clone detection: logs every match; build continues with the first ordered hit unless overridden.
* Gitignored overrides file `.antora-local-sources.yml` (see `.antora-local-sources.example.yml`) — pin by HTTPS URL or `.antora-src-*` marker basename.
* Auto-download `antora-source-resolver` from GitHub Releases into `build/.antora/bin/` (`dAutoDownload`, `dRelease`, `dRepo` config).
* Env `ANTORA_LOCAL_SOURCES_SEARCH_DRIVES=0` disables cross-drive search (tests / fast iteration).

=== Changed

* Default `searchRoots` no longer includes playbook parent; upward search covers that path.

== [0.1.0] - 2026-10-19

=== Added

* Antora extension: resolve remote `content.sources` to local clones using stable `.antora-src-*` marker files (deterministic SHA-256 basename per normalized git URL).
* Search roots: playbook dir, `%code%` / `CODE_ROOT`, `~/code`, optional `searchRoots`; hive heuristic `github.com/{owner}/{repo}` when markers are missing.
* Cache under `build/.antora/local-content-cache.json`; writes `build/.antora/antora-playbook-local.generated.yml` for debugging.
* Optional `antora-source-resolver` D CLI integration (`dBinary` config).
* Legacy `.antora-source-id` (URL in file body) supported.
