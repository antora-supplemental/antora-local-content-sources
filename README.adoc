= antora-local-content-sources

Antora extension that rewrites *remote* `content.sources` URLs to local git checkouts before the site generator fetches content.

== Why

Committed `antora-playbook-local.yml` files assume a fixed sibling folder layout (`../devcentr`, …). That breaks when clones live under `%code%/github.com/...` or other hive layouts. This extension keeps **one** committed playbook (`antora-playbook.yml` with GitHub URLs) and resolves locals at build time.

== Marker file (per content repo)

Each clone gets a **fixed short filename** at the repository root (next to `.git`):

[source]
----
.antora-source-id
----

The **stable id is inside the file**, not in the name (avoids long or awkward path segments). Body format:

[source]
----
antora-supplemental:local-content-sources:v1
id: e3cf0439ac8b22aea9c985f358734acf
url: https://github.com/org/repo
----

* `id` — 32-hex SHA-256 fingerprint of the normalized git remote (deterministic; same in Node and D).
* `url` — canonical HTTPS remote (one remote per marker, not per Antora `start_path`).

Legacy: a single-line URL-only body still works. Deprecated hash **filenames** `.antora-src-<id>` are still read if present; new repos should use `.antora-source-id` only.

Generate content for a remote:

[source,shell]
----
node -e "const m=require('@antora-supplemental/antora-local-content-sources/lib/marker-id');console.log(m.formatMarkerFile('https://github.com/org/repo.git'))"
----

== Playbook wiring

**Hubs on `@antora-supplemental/facto-stack`:** the compose pack registers this extension automatically (`mode: auto`, disabled in CI). Override on the pack require: `localContentSources: { confirmSearch: never-prompt }` or `localContentSources: false` to disable.

**Standalone** (non-pack playbooks):

[source,yaml]
----
antora:
  extensions:
    - require: '@antora-supplemental/antora-local-content-sources'
      mode: auto
      # confirmSearch: auto   # prompt on TTY when cache miss (default)
      # confirmSearch: never-prompt   # always search without asking
----

== Disk search confirmation

When cached clone paths are missing or invalid, the extension may scan drives (slow on Windows MFT).

On a **Windows desktop session** it opens a window with Why / What / How / scripting bypass and Yes / No. After Yes, that same window shows a scrollable progress log (download, search, elapsed time, conflicts). The ASCII banner and Y/n prompt are not printed. Closing the progress window does not stop the build.

Shell output is used only when there is no desktop UI, or when you force it:

* `ANTORA_LOCAL_SOURCES_CONFIRM_SEARCH=yes` -- search without prompting (agent bypass; phase lines on the terminal, ASCII, once)
* `ANTORA_LOCAL_SOURCES_CONFIRM_SEARCH=no` -- skip search; use remotes for uncached sources (still applies valid cache entries)
* `ANTORA_LOCAL_SOURCES_UI=tty` -- force the terminal banner and Y/n prompt (`shell` and `ascii` are aliases)

If the window cannot be created, the extension says so once and falls back to the terminal banner.

Non-TTY runs with no desktop (CI, SSH, service session) still default to **yes** (search, no prompt). A desktop session can show the window even when stdin is not a TTY.

Discovery finds every `.antora-source-id` candidate (MFT on Windows, walks elsewhere), then **reads the file** and matches `id` / `url`.

== Duplicate clones

When more than one checkout matches, the build lists paths and uses the first unless you pin one in gitignored `.antora-local-sources.yml` (see `.antora-local-sources.example.yml`). Override keys: `url`, `id:` hex, or legacy `.antora-src-<id>`.

== Artifacts (gitignored)

* `build/.antora/local-content-cache.json`
* `build/.antora/antora-playbook-local.generated.yml`
* `build/.antora/bin/` — optional D resolver download

== D resolver + MFT

On Windows NTFS, https://github.com/antora-supplemental/antora-source-resolver[antora-source-resolver] locates `.antora-source-id` via MFT, then validates file contents.
